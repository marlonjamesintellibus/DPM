# DPM (Digital Project Manager)

Working folder for the Intellibus Digital Project Manager: the knowledge, research and decisions behind the Figma designs.

## Files

| File | What it is | Use it when |
|---|---|---|
| `DPM-knowledge-base.md` | The main document. A general model of the product (Part A), how Intellibus fills it in (Part B), lifecycles for state machine research (Part C), the Figma screens (Part D), other use cases (Part E), open questions (Part F) | Give it to an AI agent before asking anything about DPM |
| `reference/technical-handoff-variation-H.md` | Developer handoff written from Variations G and H: metrics, integrations, privacy, tokens, decisions D1 to D22 | Detail on numbers, data sources and build decisions |
| `app/` | The DPM web app (Next.js, PGlite, Drizzle, Vitest). Run with `pnpm --dir app dev`; see `app/README.md` | Building or running the app |
| `build-plan.md` | How the app gets built: principles in code, stack, data model, flows, tokens, phases, decisions B1 to B10 | Before writing or reviewing any app code |
| `use-cases/01-update-to-plan.md` | Use case 1: a daily update to Atlas is routed to the right projects, confirmed by the speaker, and builds each project's BRAID log; PMs approve risks and decisions; Alicia is asked for a reason (L18e, L16, L6) | Scope and acceptance criteria for the first build |
| `use-cases/01-update-to-plan-machines.md` | The 16 machines in use case 1 (states, events, guards, timers) including routing, BRAID entries and matching; 79 edge cases (E1 to E99); 14 server checks on Atlas output; how each is tested | Before building or changing any state |
| `meetings/2026-10-26-silver-slipper-plaza-3.md` | Briefing on the BRAID log, who reports and who decides, project roles, streams and group-owner authorization; impact on the KB and plan; timestamped transcript | Before changing roles, visibility, RAID or the first use case |
| `research/state-machines/tla-plus-and-tlc.md` | How to check the Part C state machines with TLA+ and TLC: learning path, 5 starter specs and configs, expected results, C14 and Part F mapped to model checks | Starting formal state machine work |
| `research/state-machines/dpm-machine-map.html` | DPM machine map: every machine as one of 8 shapes, 10 stories and all checks (8 models, 45 check rows), generated by `js/build-map.mjs` | Reviewing the state machine design |

## Prompt to start an agent

> Read `DPM-knowledge-base.md` (and `reference/technical-handoff-variation-H.md` if you need detail). Answer from Part A for general questions and Part B for Intellibus facts. Cite sections. Do not invent numbers. Mark anything new as an assumption. Write in plain words with no em dashes.
